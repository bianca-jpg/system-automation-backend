<objective>
Sanitizar o corpo de `GET /health/ready` para que cada check de dependência reporte apenas um status
resumido (`"ok"` / `"fail"`), em vez do nome da classe da exceção que falhou.

Purpose: hoje cada `except` grava `checks[nome] = str(exc.__class__.__name__)` na resposta JSON de um
endpoint **público** (probe de liveness/readiness do ECS e healthcheck do compose). Isso entrega footprinting
grátis da topologia interna: `asyncpg`/SQLAlchemy distinguem `ConnectionRefusedError` de
`InvalidPasswordError` de `OperationalError` — ou seja, um atacante externo consegue diferenciar "banco
inalcançável" de "credencial recusada"; e `check_database_schema` levanta a classe própria do projeto
`DatabaseSchemaNotReadyError`, cujo nome revela que existe checagem de head de Alembic e como o código
interno se chama. Nada disso é necessário para o probe, que só olha o código HTTP (`curl -f`).

Output: `app/modules/health/routes.py` com um helper único de execução de check que devolve status resumido
e registra o nome da classe da exceção no log do servidor; `app/tests/test_health.py` com o contrato de
status HTTP preservado, guarda de regressão contra vazamento no corpo bruto e prova de que o detalhe foi
para o log em vez de desaparecer.
</objective>
