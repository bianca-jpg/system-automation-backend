<objective>
Preparar a fundação de SEC-05: a primitiva de hash do OTP e o schema capaz de armazená-lo.

`AuthOtpChallenge.code` é hoje `String(6)` e guarda o código em texto claro. O digest HMAC-SHA256 em hex tem 64 caracteres — trocar só o modelo sem migration faz o app estourar `value too long for type character varying(6)` em qualquer ambiente que aplique migrations de verdade (é assim que este app sobe: `alembic upgrade head` no CMD do `.docker/Dockerfile`). Este plano entrega a função pura + o schema; **o plano 03 é quem passa a gravar o hash**, e por isso depende deste.

Purpose: separar a mudança de schema (irreversível na prática, precisa de revisão manual) da mudança de comportamento, para que a migration seja revisada isolada.
Output: `otp_hash.py`, coluna alargada no modelo, migration 029 revisada à mão, e dois arquivos de teste.
</objective>

Criar `app/modules/auth/domain/otp_hash.py`, módulo puro (stdlib apenas: `hmac`, `hashlib`), com docstring de módulo de uma linha em português no estilo de `senha.py`, explicando que o OTP é hasheado com HMAC-SHA256 — e não bcrypt — porque a defesa contra força bruta de um código de 6 dígitos é o rate limit (SEC-07) e o TTL de 15 minutos, não o custo do hash.

Duas funções públicas, ambas keyword-only depois do primeiro parâmetro, com type hints completos:
  - `hash_otp_code(code: str, *, secret: str) -> str` — devolve `hmac.new(secret.encode("utf-8"), code.encode("utf-8"), hashlib.sha256).hexdigest()`, ou seja, 64 caracteres hex. NÃO truncar (diferente de `_opaque_key`, que corta em 32 por ser chave de Redis).
  - `verify_otp_code(candidate: str, *, stored_hash: str, secret: str) -> bool` — devolve `hmac.compare_digest(hash_otp_code(candidate, secret=secret), stored_hash)`. Nunca usar `==`.

Exportar via `__all__ = ["hash_otp_code", "verify_otp_code"]`, seguindo o padrão de `rate_limit.py`. O módulo não importa `get_settings` — quem injeta `settings.jwt_secret` é o chamador em `repositorio_otp.py` (plano 03).

Criar `app/tests/test_auth_otp_hash.py` (puro, sem banco, sem `client`) cobrindo:
  - determinismo: mesmo `code` + mesmo `secret` → mesmo digest.
  - formato: `len(...) == 64` e todos os caracteres em `string.hexdigits` minúsculos.
  - o digest difere do código em texto claro (`hash_otp_code("123456", secret=...) != "123456"`).
  - chave importa: mesmo `code` com segredos diferentes → digests diferentes.
  - `verify_otp_code` devolve `True` para o candidato correto e `False` para um candidato errado, para um `stored_hash` de outro segredo, e para `stored_hash` vazio.
  - guarda de constant-time: `assert "compare_digest" in inspect.getsource(verify_otp_code)` (impede que alguém troque por `==` numa refatoração futura).
  </action>
