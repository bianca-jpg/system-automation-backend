Fechar SEC-05 (hash em repouso) e SEC-03 (entrega do OTP por e-mail em PROD) em `repositorio_otp.py`.

Hoje `criar_desafio` grava `code` em texto claro e, em PROD, apenas registra "OTP gerado" no log — ou seja, **o usuário de produção nunca recebe o código**: o fluxo de registro e o de recuperação de senha estão funcionalmente quebrados em PROD. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| banco de dados → operador/DBA/backup | leitura de `auth_otp_challenges` deixa de render códigos utilizáveis |
| aplicação → servidor SMTP | o código sai do processo por um canal externo, com credenciais de `Settings` |
| aplicação → agregador de logs | logs de PROD são visíveis a mais gente do que o banco; código em log é vazamento equivalente |
| internet (não autenticado) → `POST /api/auth/register` e `/password/recovery` | disparam envio de e-mail para um endereço fornecido pelo requisitante |
