<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
    Toda a 5ª fonte do sync Databricks (referência tamanho→posição, `produto_tamanho_posicao`) já está implementada e testada com mocks: env var (`DATABRICKS_TABELA_TAMANHO_REF`), parse tolerante de `nr_posicao` (D-01), agregação com detecção de conflito de posição (D-03/D-04), reader, repositório de substituição e o caso de uso `sincronizar_referencia_tamanhos` com o guard de referência vazia (D-02), integrado ao commit único de `sincronizar_tudo`. A rota `POST /api/v1/ingestao/sincronizar` já devolve o contador `referencia_tamanho_posicao`. Falta a única coisa que nenhum agente automatizado deste ambiente pode simular: um sync REAL contra o Databricks.
  </what-built>

  <how-to-verify>
    Execute estes passos na sua máquina/ambiente com acesso real ao Databricks:

    1. Confirme/configure no `.env` (gitignored) as credenciais Databricks reais (`DATABRICKS_SERVER_HOSTNAME`, `DATABRICKS_HTTP_PATH`, `DATABRICKS_TOKEN`) e `DATABRICKS_TABELA_TAMANHO_REF=<endereço real da view programa_estagio.refined.system_automation_prod_tamanho_ref>`. Se o `.env` mudou, reinicie a stack: `docker compose -f .docker/docker-compose.yml up -d --force-recreate api celery_worker celery_beat`.

    2. Faça login para obter um token de admin:
       `curl -s -X POST http://localhost:8000/api/auth/sign-in -H "Content-Type: application/json" -d "{\"identifier\":\"admintec@example.com\",\"password\":\"admintec123\"}"`
       Copie o valor de `.token.access_token` da resposta JSON.

    3. Confirme a contagem ANTES do sync:
       `docker compose -f .docker/docker-compose.yml exec -T dev_db psql -U automation -d system_automation -tA -c "SELECT COUNT(*) FROM produto_tamanho_posicao;"`

    4. Dispare o sync manual (1ª chamada):
       `curl -s -X POST http://localhost:8000/api/v1/ingestao/sincronizar -H "Authorization: Bearer <token>"`
       Confirme na resposta JSON que `status` é `"success"` e que `referencia_tamanho_posicao` é um inteiro **> 0** (critério 1 do ROADMAP).

    5. Repita a contagem do passo 3 — deve ser igual ao `referencia_tamanho_posicao` da resposta.

    6. Dispare o MESMO curl do passo 4 uma **2ª vez** e repita a contagem do passo 3 novamente — a contagem deve permanecer **IGUAL** à do passo 5, nunca dobrar (critério 3 do ROADMAP — full refresh sem duplicação, provado fora de mock).

    7. Capture a amostra real para a fixture do Plano 02-05 (critério 4, LINX-03) — escolhe automaticamente um `cd_prod_cor` real com pelo menos 3 tamanhos distintos:
       `docker compose -f .docker/docker-compose.yml exec -T dev_db psql -U automation -d system_automation -tA -F"," -c "SELECT cd_prod_cor, sg_tamanho, nr_posicao FROM produto_tamanho_posicao WHERE cd_prod_cor = (SELECT cd_prod_cor FROM produto_tamanho_posicao GROUP BY cd_prod_cor HAVING COUNT(*) >= 3 LIMIT 1) ORDER BY sg_tamanho;"`

    8. Se a stack não tiver credenciais Databricks reais disponíveis agora (ambiente sem acesso): responda `sem-acesso` e descreva o bloqueio. O Plano 02-05 fica pendente até este checkpoint ser refeito com credenciais reais — não invente valores.
  </how-to-verify>

  </resume-signal>
